# Howling Whispers — full app bughunt

Date: 2026-08-23
Branch audited: `dev`

This sweep is a source-level room-by-room audit of the current development branch. It is not a substitute for a live browser/E2E pass, because the repository currently has no interaction test suite that clicks through every view.

## Summary

### Fixed during this sweep

- **Settings sidebar leaking into other views** — the enhancer is now scoped to the actual Settings page only.
- **Settings workspace layout bleeding into Add-ons / Living Cast** — non-Settings pages that reuse `.settings-page` are explicitly returned to normal single-page layout.
- **Radio reporting a false connection** — radio now reports connected/playing only after `audio.play()` actually succeeds; failures and stream errors return to disconnected state.
- **Persona privacy wording** — corrected the claim that persona data “never leaves your browser.” Saved data is local, but a compiled persona is sent to the selected story engine while roleplaying.
- **Persona memory-card typing** — the displayed `milestones` field is now represented in the component prop type.

## Room-by-room findings

### Roleplay hub — Contacts

Status: **mostly healthy / redesigned**

- Contact cards use immutable IDs for identity; duplicate display names are allowed.
- The new library layout reduces name overflow and uses wider responsive cards.
- Create/import/edit/delete/download flows are present.
- Continue to test very long names, narrow windows and minimum/maximum UI font size in a live browser.

### Roleplay hub — Locations

Status: **functional, keep regression-testing isolation**

- Location opening and Location-session construction exist as a separate path.
- Location selection uses a dedicated location selection key instead of falling back to Character identity.
- Location creation/edit/import/export/delete flows are wired.
- This remains a high-risk regression area because older bugs caused Location actions to fall into Character/Coda scenes. Any future shared Roleplay refactor must preserve the Location/Character boundary.

### Roleplay hub — Scenarios

Status: **CRITICAL — activation still missing**

Current Scenario cards are visually interactive but the Roleplay area still passes an empty open handler:

```tsx
onOpen={() => {}}
```

The Scenario domain and Scenario Factory exist, but there is no equivalent of `startLocation()` yet and `PendingPersonaStart` has no Scenario variant.

Required implementation:

1. Add a Scenario start request to `PendingPersonaStart`.
2. Add `startScenario(scenario, persona)`.
3. Construct a Scenario opening from `openingSituation`, description, atmosphere and starting conditions.
4. Resolve linked Contact/Location IDs explicitly by immutable ID only.
5. Do not silently inject unrelated Contacts or Locations.
6. Start via the persona picker just like other RP entry paths.
7. Persist enough Scenario identity in the StorySession to resume safely.
8. Add Scenario-specific context compilation instead of reusing Character fallback.

Until that is done, Scenarios must not be described as fully functional.

### Scene / Story library

Status: **generally wired**

- Character scenes, Sandbox, Whisper Mode, Common Scenes and history/resume paths are represented.
- Location sessions intentionally suppress Character-only Common Scene behavior.
- Risk: shared scene UI still assumes a selected Character in several places; any Scenario implementation must avoid forcing a fake Character solely to satisfy UI assumptions.

### Personas

Status: **fixed two concrete issues**

- Corrected misleading privacy copy.
- Corrected memory-card prop typing for milestones.
- Create/edit/delete/duplicate/import/export/default selection flows are present.
- Live-test long persona descriptions and memory-card overflow at large accessibility font sizes.

### Add-ons

Status: **layout bleed fixed; architectural duplication remains**

There are currently two Add-ons implementations:

- `features/addons/addon-manager.tsx`
- an inline Add-ons page inside `app/dreambound-app.tsx`

This is a maintenance hazard. The inline page should eventually be replaced by the dedicated `AddonManager` component so behavior cannot drift.

The Add-ons page also reused `.settings-page`, which caused Settings layout rules to bleed into it. A cross-page isolation stylesheet now prevents the Settings two-column workspace from applying to pages without a direct `.settings-grid`.

### Living Cast

Status: **layout isolation fixed; feature requires live interaction testing**

- Living Cast also reused `.settings-page` despite being an Add-on configuration page.
- It is now protected from the Settings workspace grid by the page-isolation rule.
- Enable/disable, smart/round-robin, invite/remove/reset controls are present.

### Archive

Status: **two significant bugs found — OPEN**

#### 1. Search can remain permanently busy

`BrowsePanel` sets `working` to `true` on Search, but no matching `setWorking(false)` exists. Since:

```ts
const busy = working || results === null;
```

a manual search can leave the view stuck on “Listening for echoes…” even after results arrive.

Fix: make the search request clear `working` in `finally`.

#### 2. Browse import casts incomplete search data to a full publication

Archive search returns a lightweight `SearchResult`, but Browse currently does:

```tsx
onImport(pub as unknown as ArchivePublication)
```

`SearchResult` does not contain the full profile/opening/publication payload. Importing directly from it can create an incomplete character copy.

Fix: call `archive.get(pub.id)` first, then import the returned full `ArchivePublication`.

#### 3. Dead-looking publication link

Archive cards render `/archive/{id}` links but call `preventDefault()` and no detail route was found during this sweep. This should become either a real detail view/modal or a non-link card.

### Settings

Status: **sidebar leak fixed; accessibility coupling still deserves live verification**

- Sidebar enhancer now finds only the actual page whose direct heading is `Settings`.
- Settings uses a dedicated tab workspace.
- UI font size and UI scale variables are separated at the preference layer.
- The Settings page deliberately neutralizes physical UI scale while adjusting preferences, so its own control geometry stays stable.
- Live-test slider dragging because changing Settings font size can still reflow Settings text while the pointer is down.

### Chat workspace

Status: **no new source-level blocker found in this sweep**

- Composer auto-grow logic caps height and switches to internal scrolling only beyond the cap.
- Context, Living Cast, relationship and persona controls are wired into the Chat workspace.
- This view has enough stateful controls that it should be a priority for future E2E tests: send, edit, reroll, delete, impersonate, stop generation, session persona and context panels.

### Radio

Status: **fixed**

Previous behavior set `connected: true` before browser audio playback succeeded and left `connected` true after failures.

Now connection state is set only after a successful `play()` promise and is cleared on errors/ended playback.

### Archive / Settings account and backups

Status: **source paths present; live backend verification still required**

- Local backup and server backup paths exist.
- Archive authentication is lifted into the parent for server backup access.
- These flows depend on backend/network behavior and should be verified against the deployed development environment.

### Changelog

Status: **content will become stale when Scenario activation lands**

The 0.9.0 changelog correctly states that Scenario activation is not yet implemented. Once Scenario activation is completed, add a new changelog entry rather than silently rewriting the historical 0.9.0 note.

## Cross-cutting issues

### App view type is out of sync

`AppView` currently omits `"addons"` even though the application renders and navigates to `view === "addons"`.

This may survive the current Vite build because there is no dedicated `tsc --noEmit` gate, but it is a real type-model bug and should be corrected in the main app refactor.

### No real room-to-room interaction tests

The rendered HTML test verifies that strings/classes exist in the compiled bundle. It does not click navigation, submit forms or assert state transitions.

Recommended E2E smoke suite:

- Roleplay → Contacts → scene → chat → back
- Roleplay → Location → persona picker → chat → resume
- Roleplay → Scenario → persona picker → chat → resume
- Personas → create/edit/default/delete
- Add-ons → install/enable/disable/uninstall
- Settings → each sidebar tab → leave Settings → verify sidebar gone
- Archive → search → open/import/report
- Chat → composer growth/edit/reroll/delete/context
- Radio → play failure/success/pause/stop
- mobile/narrow layout and accessibility scale extremes

## Priority order

1. **Scenario activation** — currently a no-op.
2. **Archive stuck-search state**.
3. **Archive incomplete import cast**.
4. **AppView type / Add-ons architecture cleanup**.
5. Add interaction/E2E smoke tests so these regressions are caught automatically.
